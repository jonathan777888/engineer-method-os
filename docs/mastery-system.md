# Système de maîtrise — Engineer Method OS

## 1. But

Engineer Method OS doit transformer les connaissances couvertes par quatre certificats IBM en compétences réellement utilisables dans les projets.

Les certificats concernés sont :

- IBM Full Stack Software Developer
- IBM Full-Stack JavaScript Developer
- IBM AI Developer
- IBM DevOps and Software Engineering

Le principe est de consolider les recouvrements entre certificats, conserver les spécialités propres à chacun et apprendre par fonctionnalités réelles plutôt que par répétition de cours isolés.

## 2. Modèle de preuve

Chaque élément du système suit cette chaîne :

**Certificat → Cours → Concept → Compétence → Niveau → Exercice → Fonctionnalité → Projet → Preuve GitHub**

Une preuve GitHub peut être :

- un commit compréhensible ;
- une fonctionnalité fonctionnelle ;
- un test automatique ;
- un README expliquant le problème et la solution ;
- un schéma d'architecture ;
- une API documentée ;
- un déploiement ;
- une correction de bug expliquée ;
- une démonstration de projet.

## 3. Les 5 niveaux

### Niveau 1 — Comprendre

Je peux expliquer la compétence avec mes propres mots, donner son rôle et nommer un exemple d'utilisation.

### Niveau 2 — Reconnaître

Je peux lire du code, un diagramme ou une configuration simple et identifier les éléments principaux.

### Niveau 3 — Construire avec accompagnement

Je peux réaliser une petite fonctionnalité avec un guidage pas à pas, en comprenant pourquoi chaque étape existe.

### Niveau 4 — Modifier et corriger

Je peux adapter une solution existante, comprendre un message d'erreur, chercher la cause et effectuer une correction contrôlée.

### Niveau 5 — Intégrer et démontrer

Je peux relier cette compétence aux autres couches du projet, justifier les choix principaux et produire une preuve professionnelle sur GitHub.

## 4. Les 14 blocs de compétences

### 1. Software Engineering et SDLC

**But :** transformer une idée en produit logiciel structuré.

À maîtriser : problème utilisateur, exigences, fonctionnalités, architecture, cycle de vie, qualité, documentation et découpage du travail.

**Certificats :** Full Stack Software Developer, AI Developer, DevOps, Full-Stack JavaScript.

**Preuve projet :** documenter le problème, les utilisateurs, les exigences, les flux et l'architecture avant de coder.

### 2. Agile et Scrum

**But :** avancer par petites étapes contrôlables.

À maîtriser : backlog, user stories, priorité, sprint, définition de terminé, amélioration continue.

**Certificat principal :** DevOps and Software Engineering.

**Preuve projet :** backlog GitHub avec fonctionnalités découpées en petites unités.

### 3. Git et GitHub

**But :** conserver l'historique du travail et construire une preuve professionnelle.

À maîtriser : dépôt, commit, branche, pull request, diff, historique, README et organisation du projet.

**Certificats :** Full Stack Software Developer, Full-Stack JavaScript, DevOps.

**Preuve projet :** historique de commits compréhensibles et PR documentées.

### 4. Linux et Shell

**But :** comprendre l'environnement dans lequel les applications sont exécutées et automatiser des tâches simples.

À maîtriser : fichiers, dossiers, permissions, commandes, processus, variables d'environnement et scripts shell.

**Certificat principal :** DevOps and Software Engineering.

**Preuve projet :** script reproductible de préparation, validation ou déploiement.

### 5. HTML, CSS et JavaScript

**But :** comprendre les fondations du Web.

À maîtriser : structure HTML, styles, formulaires, DOM, événements, fonctions, objets, tableaux, modules et appels asynchrones.

**Certificats :** Full Stack Software Developer, AI Developer, Full-Stack JavaScript.

**Preuve projet :** interface simple et interactive sans dépendre d'un framework.

### 6. React et interfaces utilisateur

**But :** construire une interface moderne à partir de composants réutilisables.

À maîtriser : composants, props, state, événements, formulaires, hooks, rendu conditionnel, listes et consommation d'API.

**Certificats :** Full Stack Software Developer et Full-Stack JavaScript.

**Preuve projet :** tableau de bord ou catalogue connecté à des données réelles.

### 7. Node.js et Express

**But :** créer un backend JavaScript.

À maîtriser : serveur HTTP, routes, middleware, validation, erreurs, API REST, modules et intégration de base de données.

**Certificats :** Full Stack Software Developer et Full-Stack JavaScript.

**Preuve projet :** API permettant de créer, lire, modifier et supprimer des ressources.

### 8. Python

**But :** utiliser Python comme langage de logique, d'automatisation et d'IA.

À maîtriser : variables, types, conditions, boucles, fonctions, collections, modules, fichiers, exceptions et appels d'API.

**Certificats :** Full Stack Software Developer, AI Developer, DevOps.

**Preuve projet :** script ou service Python relié à une fonctionnalité réelle.

### 9. Flask, Django et API REST

**But :** créer des applications backend et des services web avec Python.

À maîtriser : routes, requêtes/réponses, validation, modèles, ORM, authentification de base, sérialisation et API REST.

**Certificats :** Full Stack Software Developer, AI Developer, DevOps.

**Preuve projet :** API Python connectée à une base de données et consommée par une interface.

### 10. SQL, NoSQL et modélisation des données

**But :** représenter correctement les informations du projet.

À maîtriser : entités, relations, clés, contraintes, CRUD, requêtes, SQL, ORM, documents NoSQL et choix de modèle.

**Certificats :** Full Stack Software Developer et Full-Stack JavaScript.

**Preuve projet :** schéma de données justifié et opérations CRUD fonctionnelles.

### 11. Cloud et architecture cloud-native

**But :** comprendre comment une application passe d'un ordinateur local à un environnement accessible et maintenable.

À maîtriser : services cloud, configuration, variables d'environnement, déploiement, séparation des composants et concepts cloud-native.

**Certificats :** Full Stack Software Developer, Full-Stack JavaScript, DevOps.

**Preuve projet :** application déployée avec procédure reproductible.

### 12. Conteneurs, orchestration, microservices et serverless

**But :** empaqueter et découper les applications lorsque cela apporte une vraie valeur.

À maîtriser : Docker, images, conteneurs, Kubernetes/OpenShift, services, microservices, serverless et communication entre composants.

**Certificats :** Full Stack Software Developer, Full-Stack JavaScript, DevOps.

**Preuve projet :** conteneurisation d'une application simple avant toute architecture distribuée complexe.

### 13. Tests, CI/CD, sécurité et observabilité

**But :** rendre le logiciel vérifiable, plus sûr et observable en fonctionnement.

À maîtriser : tests unitaires, TDD/BDD, pipeline CI/CD, validation, principes de sécurité applicative, logs, métriques, traces et diagnostic.

**Certificat principal :** DevOps and Software Engineering, avec recouvrements Full Stack.

**Preuve projet :** tests automatisés + pipeline + gestion d'erreurs + journalisation utile.

### 14. IA générative, prompt engineering et applications IA

**But :** ajouter l'IA seulement lorsqu'elle résout un besoin clair du produit.

À maîtriser : principes d'IA générative, prompts structurés, appels de modèles, validation des sorties, contexte, recherche/récupération de connaissances lorsque pertinent et intégration dans une application.

**Certificat principal :** IBM AI Developer.

**Preuve projet :** fonctionnalité IA contrôlée, avec entrées/sorties définies et vérification de qualité.

## 5. Ordre recommandé

La progression par défaut est :

1. Software Engineering
2. Agile/Scrum
3. Git/GitHub
4. Linux/Shell
5. HTML/CSS/JavaScript
6. React
7. Node/Express
8. Python
9. Flask/Django/API
10. Données SQL/NoSQL
11. Cloud
12. Conteneurs/microservices/serverless
13. Tests/CI/CD/sécurité/observabilité
14. IA générative

Cet ordre peut être ajusté selon le projet, mais il évite de commencer par Kubernetes ou l'IA avant de comprendre l'application elle-même.

## 6. Boucle d'apprentissage par fonctionnalité

Pour chaque fonctionnalité réelle :

1. Définir le besoin utilisateur.
2. Identifier les blocs de compétences nécessaires.
3. Réviser uniquement les concepts nécessaires.
4. Construire une petite version guidée.
5. Tester le résultat.
6. Corriger les erreurs.
7. Documenter ce qui a été compris.
8. Committer la preuve sur GitHub.
9. Mettre à jour le niveau de maîtrise avec une justification.

## 7. Exemple : plateforme multi-commerçants

Fonctionnalité : inscription d'un commerçant.

- Software Engineering : règles et parcours utilisateur.
- Données : `User`, `Merchant`, `Store` et relations.
- Backend : route/API d'inscription.
- Frontend : formulaire et validation.
- Git/GitHub : branche et commit de la fonctionnalité.
- Tests : cas valide, doublon, données manquantes.
- Sécurité : mot de passe, permissions et données sensibles.
- Cloud/CI/CD : déploiement contrôlé lorsque la fonctionnalité est stable.

Une seule fonctionnalité permet donc de pratiquer plusieurs certificats sans refaire les cours séparément.

## 8. Règle d'évaluation

Le certificat prouve qu'un parcours a été complété. Engineer Method OS doit mesurer autre chose : la capacité actuelle à expliquer, utiliser, modifier et intégrer les compétences.

Le niveau initial de chaque bloc reste **à évaluer** jusqu'à ce qu'une preuve concrète soit examinée.
